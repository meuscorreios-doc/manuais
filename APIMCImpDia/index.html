API Impressão do Dia (APIMCImpDia) — Manual de Integração

Esta API permite que o cliente, usando o seu Token do MeusCorreios, busque de uma só vez todas as pré-postagens de um dia que já têm etiqueta e serviço definidos e ainda não foram impressas. Para cada objeto, a API devolve um arquivo pronto para impressão com a etiqueta de postagem + DANFE / DACE, em PDF ou em ZPL (impressoras térmicas Zebra).

Cada objeto devolvido é marcado como impresso no MeusCorreios. Assim, a próxima chamada do mesmo dia traz apenas as pré-postagens que ficaram prontas depois da chamada anterior.
TipoREST · JSON · POST
AutenticaçãoToken do cliente no corpo da requisição
Formatos de arquivoPDF (base64) ou ZPL (texto)
Escopo de cada chamadaUm dia por vez (data do lote)

Pré-requisitos

  • Token de API válido do MeusCorreios — o mesmo usado nas demais APIs (criação de pré-postagem, logística reversa etc.).
  • Pré-postagens já criadas no MeusCorreios, com serviço e etiqueta atribuídos.
  • Para receber o DANFE junto da etiqueta: chave da nota fiscal (ou da DC-e) informada na pré-postagem e o XML autorizado (com protocolo) disponível no MeusCorreios.
  • Comunicação por HTTPS.

1. Quais pré-postagens são devolvidas

Uma pré-postagem entra no retorno quando atende todas as condições abaixo:

  • Pertence ao cliente dono do Token informado.
  • Está em um lote cuja data é a data informada na chamada (se não informar, vale a data de hoje).
  • Já possui etiqueta (código de rastreio).
  • Já possui serviço definido.
  • Ainda não foi impressa.
⚠️ Ao gerar o arquivo, o objeto é marcado como impresso e recebe a data de postagem do dia, exatamente como acontece na impressão de etiquetas pelo MeusCorreios. Guarde o arquivo recebido: uma nova chamada não devolve o mesmo objeto outra vez.

2. Endpoint e autenticação

URL https://meuscorreios.app/apimcimpdia.svc/rest/
Método POST
Cabeçalho Content-Type: application/json
Autenticação Campo token dentro do corpo da requisição.
Protocolo Somente HTTPS.
ℹ️ O corpo da requisição vai sempre dentro do objeto parmIn, e a resposta vem dentro de parmOut — mesmo padrão das demais APIs REST do MeusCorreios.

3. Requisição

Campos de entrada (parmIn)

Campo Tipo Obrigatório Descrição
token texto (até 256) Sim Token de API do cliente no MeusCorreios.
data data AAAA-MM-DD Não Data dos lotes a imprimir. Um dia por chamada. Se vier vazia, vale a data de hoje.
formato texto Não PDF ou ZPL. Se vier vazio, vale PDF.
impLogo texto (S/N) Não S imprime a logomarca do remetente na etiqueta em PDF (quando cadastrada). Não se aplica ao ZPL.

Exemplos

Corpo da requisição — PDF 
{
  "parmIn": {
    "token": "SEU_TOKEN_AQUI",
    "data": "2026-10-06",
    "formato": "PDF",
    "impLogo": "N"
  }
}
Corpo da requisição — ZPL 
{
  "parmIn": {
    "token": "SEU_TOKEN_AQUI",
    "data": "2026-10-06",
    "formato": "ZPL"
  }
}
Chamada com curl 
curl -X POST "https://meuscorreios.app/apimcimpdia.svc/rest/" \
     -H "Content-Type: application/json" \
     --data-binary @requisicao.json

4. Resposta

Campos de retorno (parmOut)

Campo Descrição
erro Vazio quando a chamada foi aceita. Preenchido com o motivo quando a chamada foi recusada (ver Mensagens de erro).
data Data considerada na busca (a informada ou a data de hoje).
formato Formato usado nos arquivos: PDF ou ZPL.
quantidade Quantidade de objetos devolvidos em objetos.
objetos Lista com um item por objeto (detalhes abaixo). Quando não há nada a imprimir, o campo não vem na resposta e quantidade é 0.

Cada item de objetos

Campo Descrição
dstxlot Lote da pré-postagem no MeusCorreios.
dstxseq Sequência da pré-postagem dentro do lote.
dstxetq Código da etiqueta (rastreio).
codectcod Código do serviço de postagem.
dstxnfi Número da nota fiscal / pedido informado na pré-postagem.
dstnom Nome do destinatário.
etqSRO Link de rastreamento do objeto.
arquivo PDF: conteúdo do PDF em base64.
ZPL: comandos ZPL em texto, prontos para enviar à impressora.
erroItem Vazio quando o arquivo foi gerado. Preenchido quando não foi possível gerar o arquivo daquele objeto.

5. Conteúdo do arquivo

Cada item traz um arquivo por objeto, já com os documentos que acompanham a etiqueta:

Situação da pré-postagem Conteúdo do arquivo
Com chave de NF-e / DC-e Etiqueta de postagem + DANFE simplificado / DACE na página (ou etiqueta) seguinte.
Sem nota, com declaração de conteúdo cadastrada Etiqueta de postagem + declaração de conteúdo.
Sem nota e sem declaração Somente a etiqueta de postagem.
PDF Decodifique o campo arquivo de base64 e grave como .pdf. Uma página por documento (etiqueta, DANFE…).
ZPL Envie o texto do campo arquivo direto para a impressora Zebra. Cada documento é um bloco ^XA … ^XZ, codificação UTF-8 (^CI28), etiqueta 10 × 15 cm a 203 dpi.
ℹ️ Se o XML da nota guardado no MeusCorreios não tiver o protocolo de autorização (<infProt>), a página do DANFE sai com o aviso "Não há dados disponíveis para Emissão do DANFE/DACE". Nesse caso, reenvie a pré-postagem com o XML autorizado da nota.
Exemplo: gravar os PDFs recebidos (PowerShell) 
$r = Get-Content .\resposta.json -Raw | ConvertFrom-Json
foreach ($o in $r.parmOut.objetos) {
    [IO.File]::WriteAllBytes("$($o.dstxetq).pdf", [Convert]::FromBase64String($o.arquivo))
}

6. Fluxo recomendado

  1. Crie as pré-postagens no MeusCorreios (pela tela, por integração ou pelas APIs de pré-postagem).
  2. Quando for imprimir, chame a APIMCImpDia com o Token, a data do dia e o formato desejado.
  3. Para cada item de objetos:
    • se erroItem estiver vazio, grave ou envie o arquivo para impressão;
    • se erroItem estiver preenchido, registre o objeto para conferência.
  4. Repita a chamada quantas vezes quiser ao longo do dia: cada chamada traz apenas o que ficou pronto desde a anterior.
✅ Como os objetos devolvidos são marcados como impressos, não há risco de imprimir duas vezes a mesma etiqueta por chamadas repetidas.

7. Mensagens de erro

Onde aparece Mensagem O que fazer
erro Token Invalido Confira o Token (sem espaços antes ou depois) e a validade dele.
erro Acesso Restrito [motivo] O acesso do cliente está bloqueado. Entre em contato com o suporte do MeusCorreios.
erro Formato invalido: use PDF ou ZPL Informe PDF, ZPL ou deixe o campo formato vazio.
erroItem Nao foi possivel gerar o arquivo da etiqueta O objeto não foi marcado como impresso e volta na próxima chamada. Se persistir, acione o suporte informando lote e sequência.
⚠️ Quando o campo erro vem preenchido, nenhuma pré-postagem é processada nem marcada como impressa.

8. ZPL também nas APIs de criação de pré-postagem

As APIs APIMCCriPrePos e APIMCCriPreDANFE, que criam a pré-postagem e já devolvem a etiqueta, passaram a aceitar ZPL no campo impetq, sem nenhuma mudança para quem já usa PDF:

impetq Retorno
PDF, PDFDCE, PDFNFE Como antes: PDF em base64 no campo etqPDF.
ZPL, ZPLDCE, ZPLNFE Etiqueta + DANFE/DACE (ou declaração de conteúdo) em ZPL, em texto, no novo campo etqZPL.

FAQ de suporte

Chamei a API e não veio nenhum objeto.
Confira se a data é a dos lotes onde estão as pré-postagens e se elas já têm serviço e etiqueta atribuídos. Pré-postagens já impressas (pela tela ou por uma chamada anterior) não voltam.

Perdi o arquivo de uma etiqueta já devolvida. Como reimprimir?
A APIMCImpDia devolve cada objeto uma única vez. Reimprima pela tela de Pré-Postagem do MeusCorreios ou acione o suporte informando lote e sequência.

Posso buscar vários dias numa chamada só?
Não. Cada chamada considera um único dia. Para dias diferentes, faça uma chamada por data.

O DANFE saiu com "Não há dados disponíveis para Emissão do DANFE/DACE".
O XML da nota guardado no MeusCorreios não tem o protocolo de autorização. Reenvie a pré-postagem com o XML autorizado da nota.

A etiqueta ZPL saiu cortada ou deslocada.
O ZPL é gerado para etiqueta 10 × 15 cm em 203 dpi e não define o tamanho da mídia. Configure a impressora para esse tamanho de etiqueta.

O campo objetos não veio na resposta.
Isso significa que não há nada a imprimir no dia (quantidade = 0). Trate a ausência do campo como lista vazia.
